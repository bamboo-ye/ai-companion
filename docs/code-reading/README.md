## 读 Go 时反复出现的写法

| 写法 | 在这个项目里的意思 |
|---|---|
| Handler → Service → Store | Handler 处理 HTTP 和身份；Service 执行业务规则；Store 负责 SQL、事务和并发约束。 |
| ctx context.Context | 携带取消、超时和 Trace；不要把它等同于模型上下文。 |
| value, err := ... | 接收结果并显式检查错误；错误返回常常就是当前行为的终止分支。 |
| errors.Is / errors.As | 判断领域错误或提取结构化错误类型，决定 404、409、重试或终态。 |
| interface + 类型断言 | 依赖最小能力，例如只有实现 WikiStore 才能编译 Wiki。 |
| *bool / *int | 区分未提供、false/0 和真实值；审批和配额尤其依赖此区别。 |
| defer tx.Rollback() | 任何提前返回都回滚；成功 Commit 后延迟 Rollback 不会撤销提交。 |
| revision / expected | 乐观并发版本；旧页面或旧 Worker 不能覆盖新状态。 |
| lease_owner / lease_expires_at | 有时限的执行权；任务可被接管，结果提交必须重新检查。 |
| true/false, error | 不同方法含义不同：可能是“是否领取过任务”“是否新建”“是否改变状态”；每节会说明。 |
| UTC + timezone | 数据时间统一保存，用户输入解释和日/月边界按本地时区计算。 |

## 四种 ID 要分清

- Conversation ID：多轮对话容器。
- Message ID：一次发言或一个气泡；助手通过 ReplyToID 关联原用户消息。
- Agent Run / Generation Job ID：处理一次输入的运行记录。它可失败、取消、等待或恢复。
- Skill Run ID：Agent 某一步实际工具任务；一个 Agent Run 可产生多个 Skill Run。

“运行 completed”只描述对应那一层。ToolPreparation.status=completed 不代表后台 Skill 已完成；文档已 queued 不代表已经解析；HTTP 202 不代表业务已经成功。各章专门指出这些状态边界。

## 当前实现与配置边界

当前消息 intake 已共用 BuildContext；记忆支持可选语义分数和纠正链；文档有 Wiki 编译、依赖可见性与编辑版本；管理员 Web 登录已有 Passkey；额度按用户、全局、套餐三层覆盖。这些能力都按本次工作区源码核对。语义检索仍需要配置启用，不能据此假设本机当前启用了外部 Embedding。

## 文档与源码一致性

源码链接采用当前工作区绝对路径，适合在本机点击对照；文件名与函数名也保留在正文。移动仓库后，生成章节的源码链接可通过重新生成更新；第 00、12 章是手工教材，其中的绝对链接和示例命令路径需同步调整。source-manifest.json 保存本次涉及文件的 SHA-256。

从仓库根目录执行：

```sh
node docs/code-reading/build.mjs --check
```

该命令只检查生成文档、摘录和源文件指纹是否一致；它不执行业务，也不证明人工解释一定正确。若代码变化，先核对 guide.mjs 中行号与解释、teaching.mjs 中的案例，以及 symbols.mjs 中的变量/函数卡片，再执行不带 --check 的命令更新摘录。不要在代码已经偏移时直接刷新文档冒充解释仍然有效。
