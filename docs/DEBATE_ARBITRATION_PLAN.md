# 有界辩论与证据仲裁升级方案

状态：A/B 已实施；已补齐浏览器交付验收、C 的配对评测门槛工具，以及 D 的既有来源范围内 Wiki 后台补证与记忆澄清。默认关闭。真实四组模型采样、人工标注、在线影子运行与生产灰度尚未执行；当前工具仅离线读取测量记录，不声称完成这些运行。当前行为见 [证据仲裁](ARBITRATION.md)，下文保留最初设计依据。

依据：2026-09-30 本地工作区代码，当前图版本 `ai-companion-supervisor@3.71.0`。仓库已有未提交工作，本方案不代表线上部署状态。

## 1. 建议与范围

建议在已有 `evidence-arbitration-v1` 上增量建设“独立判断 → 结构化质疑 → 定向补证 → 仲裁 → 收敛判定”。辩论用于暴露可验证的分歧，仲裁用于形成可执行、可追溯的处理结果。两者均不能用多数意见代替证据。

| 环节 | 优先级 | 建议 |
| --- | --- | --- |
| Work 研究、多文档问答 | P0 | 对同口径冲突、关键结论缺少支持启用；优先核对原文、适用范围、单位与生效时间 |
| 回复与文档生成前的内容审校 | P0 | 围绕具体事实缺陷和互相冲突的修改要求展开；保留最多一次正文修订 |
| Wiki 多来源冲突 | P1 | 复用证据、状态与校验协议；多轮补证接后台任务，不直接拉长现有单次仲裁请求 |
| 长期记忆关系 | P2，有限适用 | 仲裁只标注关系；个人偏好、经历与新旧陈述无法由模型投票确定，需要用户明确纠正或补充适用时间 |
| 简单聊天、单次生活工具、纯风格偏好 | 不默认接入 | 无明确争议时跳过；纯偏好按用户要求处理 |
| 工具权限、参数 Schema、审批、动作预算、数据库版本检查 | 不参与语义裁决 | 继续由确定性代码负责，不给仲裁增加授权能力 |

首期以研究和事实审校为范围。内容审校通过不代表渲染后的 PPT/PDF 版面通过，现有渲染与制品检查继续独立执行。

## 2. 已有基础与需要补齐的缺口

已有能力：

- `parallel_tasks.py` 已有只读研究 DAG、独立分支结果、预算预分配和检查点恢复；审校有 grounding / clarity 两个角色。
- Python `arbitration.py` 已校验候选归属、引用 ID、逐字摘录和研究候选的原始来源，递归展开分析依赖，按输入哈希复用结果。
- Go `internal/arbitration/arbitration.go` 已被 Wiki 和记忆调用；有输入上限、超时及保留分歧的降级方式。
- 当前研究分歧未解决时阻止文件生成，文本回答保留待核对提示；记忆仲裁不会自行覆盖旧记忆。

需要补齐：

1. **并行不是完整的独立性证明。** 首轮审校调用已有上下文隔离，但没有持久化的独立性报告；依赖研究分支可以读取前置分析，不能被当成新的独立判断。grounding 与 clarity 检查的维度不同，也不是同一事实的两份独立佐证。
2. **`need_evidence` 没有补证路由。** 当前设置 `parallel_plan.arbitrated` 后继续生成、修订或终止，不会定向读取新资料并复核争议。
3. **处理成功和争议解决混在一起。** Python/Go 在裁决结构校验通过后把记录状态设为 `resolved`，即便逐项动作仍有 `retain` / `need_evidence`。现有交付判断还检查逐项动作，不宜把这个字段混用直接理解为已经放行了争议。
4. **一轮状态不适合直接扩成多轮。** Python 的研究候选 ID 依赖列表位置，裁决后会过滤 `research_results`；`finalize` 扫描所有历史仲裁中的未解决项。增加补证后，需要稳定候选、不可变原始结果和“当前有效裁决”视图，避免旧争议永久残留。
5. **引用存在不等于逻辑支持。** 逐字摘录校验不能证明相关性、来源真实性或证据能够推出结论，需要显式记录支持关系和未回答的反证。

## 3. 原则一：独立性必须可检查

### 3.1 首轮隔离提交

对同一争议冻结任务约束、候选版本和原始证据快照，提供给两条隔离分支：

- 证据核验者：检查结论由什么原文支持，范围、时间、单位是否一致。
- 反例核验者：检查反证、遗漏条件和可能使结论失效的情形；允许结论一致，不要求为反对而反对。

首轮双方均不能读取对方结论、前次仲裁意见或上游分析摘要作为事实依据。已有结果只有在问题一致、证据快照一致且通过隔离校验时才可复用。待审候选可以共同可见，但必须标为被检查对象，不能算独立事实来源。

双方提交并持久化后，才向第二轮提供结构化质疑。第二轮明确标记为交叉复核，不再宣称判断互相独立。记录结论、证据、反证和改变判断所需条件，不保存或要求模型内部思维链。

### 3.2 运行时生成独立性报告

保存 `participant_id`、角色、模型与 Prompt 版本、输入快照哈希、可见证据 ID、依赖链和首轮提交记录。这些字段由调度器生成，不能由模型自行宣称。

校验分为三个维度：

| 维度 | 检查方式 | 处理方式 |
| --- | --- | --- |
| 上下文隔离 | 输入只能含冻结资料、任务约束和本角色指令；检查禁止的候选输出与裁决依赖 | 失败的结果不得作为独立判断；有预留额度时重建隔离输入一次，否则保留分歧 |
| 来源依赖 | 沿原始文档、工具结果与派生引用建立来源链 | 同一文档多个片段、同一原文的转述不算多个独立来源；未知来源关系标记未知 |
| 模型相关性 | 记录端点、模型和配置指纹 | 同一模型标为相关风险；可配置异模型复核，但不同模型也不自动获得“统计独立”认证 |

结构隔离可以用代码验证，统计独立和真实准确率必须通过评测观察。即使两位参与者同意，也不能提升证据等级；单一来源也可以支持其明确记载的事实，无需人为凑足来源数量。

## 4. 原则二：继续讨论必须有实质增量

### 4.1 把 `need_evidence` 变为可执行请求

裁决保留现有动作，并为 `need_evidence` 增加 `evidence_requests`：

- 对应哪个 `issue_id`；
- 缺少什么事实、原文范围或有效时间；
- 哪种新信息可以区分候选；
- 建议使用哪个已有只读工具和有界参数。

仲裁者不直接调用工具。协调节点校验请求、合并重复查询、预留动作额度，再通过现有 Go Tool Gateway 执行。首期使用已有文档查询、Wiki 搜索/读取及产品知识工具，不隐式接入新的外网来源。

同样的查询不能因轮次变化而自动重跑；只有读取范围、来源版本或要检验的条件有实质变化才产生新请求。确需用户补充事实时返回具体待确认项，不能自行代答。

### 4.2 新证据登记与去重

新证据元数据至少包含来源 ID、版本、内容哈希、原文定位、工具执行引用、来源依赖、访问权限依赖和首次进入本会话的轮次。元数据从工具结果与服务端映射构造，不信任模型填写的来源属性。

新增信息可以是同一文档此前未读到的相关原文、另一份可追溯原始资料、明确的版本替代说明，或可复现的工具校验结果。以下不计为有效增量：

- 同一片段换一个查询或 URL 再返回；
- 只改变说法的模型总结、参与者互相引用；
- 只有抓取时间变晚、相关内容没有变化；
- 与当前争议没有关系的新增资料。

哈希与位置用于确定性去重；相关性与语义新意需单独评估，不能把“不同哈希”直接等同于“新证据”。同源新片段可以有新信息，但不增加独立来源数量。来源关系不明时保守标注，不宣称完成了全网同源识别。

首轮可以利用已有证据纠正一次明确误读、单位或范围错误；完成首轮裁决后，若仍未解决且没有有效新证据，就不启动下一轮模型争辩。缺乏新证据是停止理由，不是问题已解决的证明。

新证据需要改变候选事实时，由分析分支产生新候选 ID，并记录 `supersedes_claim_id`；原候选保留。仲裁继续只能选择已登记的候选，不能自行编造新事实。

## 5. 原则三：显式区分收敛与停止

拆开三类状态：

- `call_status`：模型调用及协议校验是否成功。
- `resolution_status`：`resolved` / `partially_resolved` / `unresolved`，由逐项有效裁决汇总。
- `termination_reason`：已解决、无新证据、独立性失败、重复状态、预算不足、超时或需用户澄清。

**争议解决**要求逐项裁决覆盖候选、引用有效且支持关系已说明，对已登记的关键反证给出有依据的处置；当前证据不存在仍未处理的阻断项。最后由确定性门禁校验结构、版本、权限和必需字段。支持关系本身仍是语义判断，不能宣称已由程序证明事实为真。

**停止但未解决**包括：补证无增量、没有可用来源、独立性不满足、输入反复重复、达到预算或时间上限。保留候选和分歧；文本输出说明缺少什么，文件任务继续遵守现有未解决研究分歧不生成的规则。

每轮计算包含规范化问题、候选、证据版本、约束和裁决摘要的指纹，检测重复状态；措辞变化不算进展。换模型、换措辞或重新创建会话不能刷新同一 Run 的总预算。

已有来源版本或权限变化时，旧裁决失效；新版本需要建立新快照并重新核验。不能把不同版本的两轮结果拼成“已收敛”。

## 6. 建议的执行状态机与上限

```text
发现结构化争议 / 明确审校问题
  → 冻结问题、原始证据、候选和预算
  → 首轮两方隔离判断
  → 独立性与引用校验
  → 仲裁
      ├─ 逐项已解决 → 交付门禁 / 按要求修订并复核
      ├─ need_evidence 且有额度 → 校验补证请求 → 只读获取 → 增量检查
      │    ├─ 有实质增量 → 双方交叉复核 → 再次仲裁 → 终止判定
      │    └─ 无实质增量 → 保留分歧并停止
      └─ 其他不能解决的情况 → 保留分歧并停止
```

首期建议初值，需经代表性样本校准：

- 每个 Run 最多一个新增辩论会话，批量处理至多 12 个争议；溢出项明确保留，不能静默丢弃或无限拆会话。
- 最多两轮：一轮独立判断和至多一轮补证后的交叉复核；新增模型调用最多 6 次，即每轮两方判断加一次仲裁。复用的合格结果不重复调用；失败调用和隔离重做同样占这个额度。
- 新增只读工具调用最多 2 次；超额请求排序后截断并保留未覆盖原因。超限结果不静默截成不完整证据，需报告覆盖情况。
- 辩论会话新增墙钟上限建议 60 秒，包含排队和外部等待；跨检查点保存截止时间，恢复不重置时钟。
- 继续受现有 Run 的调用、Token、费用、动作和节点额度限制，不提高现有总预算。先预留后续综合/修订/复核的所需额度，再决定能否开始辩论；修订与复核成本也进入总账。
- 正文仍最多修订一次。修订后可用现有审校链路复核，但不得新开辩论循环；仍有无法解除的问题则停止交付。
- 新增 `AGENT_DEBATE_MODE=off|requested|on_conflict`，初始默认 `off`；先影子评测，再小范围开启 `requested`，证据充分后才考虑 `on_conflict`。

辩论的 6 次调用是新增会话上限，不是整条生成流程的总调用数。现有研究、生成、修订和复核仍另有调用，评测应比较完整 Run 成本与延迟。

## 7. 数据与实现落点

建议协议升为 `evidence-arbitration-v2`。Python 与 Go 共用版本化 JSON Schema 和正反例契约数据，不强行共享跨语言运行时。

新增数据概念：

| 记录 | 内容 |
| --- | --- |
| `debate_session` | Run、模式、冻结快照、轮次、截止时间、预留与实际预算、终止原因 |
| `claim` / `issue` | 稳定 ID、原始提出者、事实口径、候选版本、前驱关系 |
| `evidence` | 原始引用、内容与版本指纹、来源依赖、ACL 依赖、工具执行引用 |
| `position` / `challenge` | 支持/反对/不确定、证据 ID、具体反证、需要补充的事实 |
| `independence_report` | 隔离结果、来源重合与未知关系、模型配置及相关风险 |
| `arbitration_round` | 本轮输入哈希、逐项裁决、支持关系、补证请求、调用与解决状态 |

ID 绑定 Run/任务、事实口径和候选内容版本，不依赖列表下标。原始候选与轮次记录只追加；生成回答使用单独的已采纳视图，展示分歧使用当前有效裁决视图。

| 文件或模块 | 计划改动 |
| --- | --- |
| `workers/python/src/ai_companion_worker/arbitration.py` | v2 输入输出校验、逐项状态汇总、当前有效裁决；保留 v1 记录读取 |
| 新建 `debate.py` | 会话状态机、独立性报告、证据增量检查、收敛与停止判定 |

| `agent_runtime.py` | 新状态与图路由、当前有效争议汇总、交付门禁；修正扫描全部历史未解决项的方式 |
| `agent_governance.py` | 新节点可写字段、调用上限、预算计费与图版本升级 |

研究补证可以查询当前用户有权限的其他资料，但新资料必须纳入快照与来源依赖。Wiki 如引入新来源，必须重新计算整个页面权限交集和版本依赖，不能沿用原来的较宽可见范围。

复用检查点保存会话与轮次；稳定键至少绑定 Run、会话、轮次、任务及规范化请求。已持久化结果复用；未完成异步任务恢复查询。模型响应尚未落盘时的故障窗口依然存在，不作外部调用恰好一次的承诺。

缓存键绑定用户/权限依赖、来源版本、候选、任务约束、协议、Prompt 与模型配置。升级图版本，沿用现有旧图 Run 隔离策略；关闭功能只影响新 Run，不把进行中的 v2 检查点静默解释成 v1。

第一期 Python 会话可放入已有 LangGraph 状态；Go 记录扩展优先使用现有 JSON 字段。是否增加独立审计表由查询、保留期和数据量决定，不在方案阶段假定无需任何迁移。

## 8. 分期交付与验收

**阶段 A：协议与状态基础。** 先拆分调用成功与争议解决，建立稳定候选、不可变历史、当前有效裁决和跨语言契约。特性默认关闭，现有路径可回归。

**阶段 B：研究与审校闭环。** 接入首轮隔离、定向补证、增量门禁、第二轮复核和确定性停止；补齐失败恢复和完整 Run 预算统计。首期交付以此为止。

**阶段 C：评测与灰度。** 使用同一任务集比较当前 v1、单 Agent 定向补证、v2 辩论补证，并加入同资料重复调用的对照；约束总预算，区分收益来自补证还是多人讨论。影子模式不改变实际裁决与交付结果，仍记录真实额外成本。

**阶段 D：Wiki 与有限记忆接入。** 优先 Wiki 后台补证；记忆只增强关系说明和向用户提出具体澄清项，不自动替代记录。

必须覆盖的验收用例：

| 类别 | 预期 |
| --- | --- |
| 无分歧 / 功能关闭 | 不增加辩论模型调用 |
| 首轮读取对方结论或依赖分析 | 校验失败，不标为独立判断 |
| 同模型、同源转述、镜像文档、未知来源关系 | 不伪造独立性，不按票数升级可信度 |
| 同一原文未读部分揭示范围差异 | 登记有效新信息；同源片段不增加来源数量 |
| 重复查询、同片段改写、只改时间戳 | 不视为新证据，不触发第二轮 |
| 未知候选、伪造引文、真实但不支持结论的引文 | 前两者确定性拒绝；最后一种纳入真实语义评测与保留不确定性的测试 |
| `need_evidence`、部分解决 | 调用成功也不能标成全部解决；完整记录未解决项 |
| 新证据解除早先争议 | 当前视图更新，历史保留；最终回复不再将已解除旧轮次标为未解决 |
| 超预算、超时、失败重试 | 如实计费、保留结果、及时结束，不重置额度或轮次 |
| 在每个新节点中断并恢复 | 已落盘结果复用；只恢复未完成步骤，权限和版本重新验证 |
| 来源更新、删除、权限撤回、跨用户访问 | 缓存失效，无旧证据或理由泄漏；Wiki 扩源后权限收紧 |
| 文件任务分歧仍在、修订复核失败 | 继续阻止不合格交付，不靠多数意见放行 |

离线确定性测试要求上述契约全部通过。真实模型评测使用人工标注的代表性研究/审校样本，重点统计错误采纳率、误驳回率、分歧解决率、补证有效率、错误共识率、P95 延迟和完整 Run 成本，并报告样本量与不确定性。

灰度门槛应在评测前按业务容忍度确定。首先要求错误采纳率不劣于当前基线，再看解决率提升能否覆盖延迟和成本；不能把“更多问题被判为 resolved”单独作为成功标准。若收益仅来自补证，就优先保留更简单的补证路径。

现有 `test_arbitration.py`、`test_parallel_tasks.py`、Go 仲裁/Wiki/记忆测试继续回归；新增独立性、证据增量、收敛与恢复用例并接入已有 `eval-agent-arbitration`。本方案的确定性验收已接入自动化；真实模型准确率与成本收益需要单独评测，不能由桩测试推断。

## 9. 示例

研究结果 A 说“项目预算 10 万”，B 说“项目预算 30 万”，两者原先都没有抽出适用范围。

1. 双方隔离核对原文，发现现有片段没有说明预算口径，不按人数或置信度选值。
2. 仲裁返回需要核对预算表的范围和脚注，协调器只读获取相关原文。
3. 新读到的脚注明确“10 万为试点，30 万为全年”。登记为同源新增证据；分析分支创建带正确范围的新候选。
4. 双方复核后，仲裁选择按范围并列保留，输出清楚的限定条件。
5. 如果没有找到脚注或其他有效依据，则以“缺少范围依据”结束，保留两个候选；不继续换措辞辩论，也不生成包含未经确认唯一金额的文件。
