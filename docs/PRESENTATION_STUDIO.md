## 已实现的产品边界

每页可选版式包括封面、章节、陈述、列表、双栏、对比、步骤、时间轴、指标、引用、图文、图表、表格、目录、四象限和结尾。主题独立于内容，文字、表格和图表在 PPTX 中仍可编辑，图表包含内嵌工作簿。

「应用修改」重新计算版式并保存任务版本；草稿在修改后自动保存到 IndexedDB，兼容旧版 localStorage 草稿并在存储失败时明确提示。导出使用当前设计稿，不能误导出旧预览。复制页面保留图表编辑数据，替换副本图片不影响原页；撤销/重做同步恢复页面选择与编辑字段。页面锁定保留内容与手工位置，超出容量时显示问题并阻止交付。目标页数允许随内容调整，不通过截断文字或填充虚构内容凑页。

单页快捷指令支持按版式名称切换、拆页和关闭动画。整稿的自然语言设计通过聊天中的 `style_prompt` 或工作台的「用一句话描述风格或用途」进入 LLM 设计流程。聊天侧继续使用现有内容规划与资料提取能力。

支持的导入为文本 PDF、TXT、Markdown、本工作台的 `.deck.json` 和 `.theme.json`。不包含任意第三方 PPTX 母版的无损逆向导入、扫描件 OCR、多人实时协作、自由绘图或 Morph 动画。图片展板目前为单图；图表目前为一个数据系列、最多 12 个分类。表格编辑每页输入最多 8 列、12 行，容量不足会分成续页；超过单条记录容量则要求用户调整。

## 成品模板与页面库

开始制作页提供「浏览成品模板」：季度复盘、项目提案、课程讲解各 7 页，可以先按用途筛选、搜索并逐页预览，再创建独立设计稿。模板的「待填写」内容需要替换为实际资料，完整模板不预填虚构业绩。

编辑区的「添加页面」按开场与收尾、观点与对比、流程与计划、数据与证据四类组织 18 种常用版式。插入位置在当前页之后，保留整稿品牌、主题与动画，可以撤销、重做。图表页明确标注示例数据；编辑数据后保持所选条形、柱状或折线图类型。四种图片版式仍在页面设计面板中选择和配图。

模板缩略图与导出使用同一个布局引擎。`presentation_library.py` 是唯一模板来源，`web/public/presentation-library.json` 是生成的浏览器预览目录（约 164 KB，按需加载）；测试校验两者一致，并实际渲染三套模板及页面库。布局或模板变更后执行：

```sh
workers/python/.venv/bin/python -m ai_companion_worker.presentation_library web/public/presentation-library.json
```

「演示设置」修改整稿标题及听众，并可同步封面标题，锁定封面保持原文。删除图片页面时释放无引用资源，撤销后仍能恢复图片。页面库弹窗支持键盘焦点约束、Esc 关闭及窄屏布局。

## 运行与运维

文档 Worker 需要 `libreoffice-impress`、`fonts-noto-cjk` 和 `fonts-wqy-zenhei`。三个相关 Dockerfile 已补齐依赖；2026-09-30 已构建并部署本机 Docker 镜像，未发布远程生产环境。

可通过 `PRESENTATION_SOFFICE_PATH` 指定渲染器，通过 `PRESENTATION_FONT_DIR` 指定字体目录；默认也会读取进程工作目录下的 `.data/presentation-fonts`。每次渲染使用独立的 Office profile 和临时目录，最长 90 秒。未安装渲染器时允许导出 PPTX/设计稿，并明确显示未验证、没有 PDF；已安装但渲染失败、缺字或越界时阻止交付。

`office.pptx_outline` 与 `office.pptx_generate` 的接口版本升级为 2.0.0。两者输入上限均为 30 MiB，HTTP 请求按技能预算解码，超限返回 413，避免含图片的设计稿被通用 1 MiB 请求限制拦截；其他技能仍使用自身预算。单个输出文件受 32 MiB 限制。Worker 响应上限为 128 MiB，用于同时容纳设计资源、PPTX、PDF 和预览图。

核心文件：

- `workers/python/src/ai_companion_worker/presentation_design.py`：设计稿校验、内容规划、主题、场景、布局质量门与有限修复。
- `presentation_render.py`：原生 PPTX、动画、独立渲染与缺字检查。
- `presentation_studio.py`：既有来源质量门与新设计流程适配。
- `web/app/presentation-model.ts`：历史、编辑、数据导入的纯逻辑。
- `presentation-canvas.tsx` / `presentation-studio.tsx` / `presentation-studio.css`：预览、编辑器、试播与响应式样式。
- `presentation-draft.ts` / `presentation-download.tsx`：大图片草稿持久化与认证文件下载。
- `presentation_library.py` / `presentation-library.tsx`：模板源定义、真实页面预览与插页弹窗。

### 对话式设计与通用分层图解

能力面向任意项目与资料，不依赖「伴AI」这个项目名。工作助手在对话中提取用途、受众、视觉风格和组织要求，再调用通用 PPT 生成工具。示例：「把这些温室管理资料做成一页绿色科技感架构图，目标在顶部，三类业务并列，设备与数据作为底层支撑。」工作台也可填写相同风格描述，目标页数设为 1；每个 Markdown 章节对应一个内容模块。

风格模型返回受约束的设计数据：自由配色、中文标题/正文字体、字号层级、圆角、逐页布局、图解区域和动画。`capability-map` 是通用分层版式，可组织 2–10 个模块，支持可选的顶部定位、1–4 个主要分区、侧栏、0–3 个支撑层分区和底部说明。区域按内容 ID 引用，必须完整且不重复；响应 schema 限定每页可用 ID 和版式，语义检查失败最多自动修正一次，两次调用共享单次预算。无需为新项目编写新模板。多页演示继续选择列表、对比、时间轴、图文、原生图表和表格等合适版式。

内容规划与视觉设计分别负责：聊天根据用户提供的资料组织事实，风格模型只能安排已有内容，不能改写数据、增加业绩或丢弃模块。「伴AI」是其中一个内置知识来源，使用已核对的公开产品事实与原始品牌图标；参考照片仅用于理解分层组织形式，不复制其财经业务。未知项目需要用户提供资料。

新建时 `project_name` / `revision_of` 默认为空；用户显式提供的资料优先于内置项目名。连续修改时，聊天工具使用 `revision_of: "latest"`，只读取当前账户、当前对话里最近成功生成的设计稿，再按新描述设计。工作台可用「继续描述风格或用途」重新设计现有内容。手工保存和导出不会再次调用模型。对保存稿与内置稿的导出检查使用设计稿中实际可见的内容，不再要求空缺的旧 Markdown 输入；正文用途、语言、来源覆盖、表格和排版质量门继续执行。聊天交付检查识别附带 PNG；模型观察保留正文、风格与质量证据，移除预览图、场景坐标和内嵌图片，原始设计稿仍由工作台读取，避免后续对话被 base64 图片撑满。锁定的页面或对象需先解锁才可整稿重设计；字体仅在已安装的三种中文字体中选择。

模型必须支持结构化 JSON 输出。`MODEL_PRESENTATION_STYLE_NAME` 留空时沿用 `MODEL_TRANSLATION_NAME`，模型须固定且使用现有 OpenRouter 服务配置。单次风格规划预算上限 25,000 micros；图像和风格的整次生成预算上限 275,000 micros。未配置模型时明确报错，既定主题仍可用；不会把固定模板选择假称为 AI 设计。预算、失败用量与来源检查沿用现有任务治理。

交付前进行模块完整性、配色对比度、字体、文字容量、边界和重叠检查，再由 LibreOffice 渲染实际 PPTX，检查页数、缺字和文字边界。单页图解另提供约 1920×1080 的高清 PNG；文字、形状、连线仍在 PPTX 中独立可编辑。讲述节奏通过分组淡入与转场表达，不承诺任意自由动画或自动生成任意拓扑。

本轮验证包含非伴AI的智慧温室与课堂教学案例，以及暖色投资人、蓝白课堂和黑白评审风格。实际模型输出、原生文件与渲染报告存放在 `artifacts/presentation-studio/project-style/`。

运行稳定性修复：未启用知识投影时，不把会立即正常返回的投影任务加入常驻 Worker 监督器，避免整个任务进程正常退出后循环重启。

### 整稿编排与混合页面（2026-10-01）

默认以完整演示为单位处理内容与风格。工作台主入口填写整稿资料、听众和用途；内置项目入口折叠为辅助入口，默认提供八页完整介绍，仍可明确选择一页能力图。伴AI知识只是事实来源，使用相同的通用内容规划、风格规划和渲染流程。

多页 Markdown 以 `##` 表示内容页。需要分层图解的某一页，用 `###` 表示该页内的 2–10 个模块，其余页继续使用要点。例如：

```markdown
## 背景与目标
- 已有事实
- 目标说明
## 系统构成
### 业务入口
- 入口职责
### 数据支持
- 数据职责
## 实施流程
- 准备
- 验证
```

模块不会被展开成额外幻灯片，也不会导致整套演示变成单页。模块页中的事实必须全部归组，空模块、过多模块和缺失内容会被拦截。图解页不会关闭其他页面的图片能力。

LLM 通读整稿后返回 `style_profile.storyline` 和各页 `purpose`、`animation`、`duration_ms`，在统一配色、字体与字号层级下分别安排表达与动画。模型响应乱序不能改变用户原页序；每页仍必须恰好出现一次，表格、图表、文字、来源与图片保持完整。结构说明仅显示在工作台「整稿结构与节奏」中，不写到读者可见幻灯片上。原设计稿没有这些新字段也可继续恢复、编辑与导出。全稿动画选择会重设未锁定页面的动画继承，避免被逐页规划覆盖而无效。

`test_presentation_whole_deck.py` 覆盖八页混合演示、内置项目多页复用、图解页与其他图片页共存、对话输入路由、模块事实检查、逐页动画原生导出，以及图表与表格在重新设计后仍可编辑。
