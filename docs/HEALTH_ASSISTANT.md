# 健康助手

健康助手来自 `healthy_care` 的个人健康空间。登录伴 AI 后从侧栏进入，无需另建账号。使用图文对话记录健康变化，核对草稿后写入病程、实际用药或随访提醒。在「我的与隐私」可直接导出或清除记录。健康助手用于日常记录和护理参考，不提供诊断、处方或在线就诊。

## 第一次记录

1. 在「每日健康」输入描述，或打开「健康对话」。写明时间和观察到的变化，需要时点「添加图片」。每条消息最多 4 张 JPEG、PNG 或 WebP，单张最大 8 MiB。页面文字输入最多 12,000 字符。
2. 发出消息后等待回复。有草稿时核对日期、内容和已有记录，再点「确认保存」或「不保存」。对话消息在发送时保存，确认操作保存的是结构化记录。处理失败时可使用原消息旁的「重试」。
3. 在「我的病程」看正在跟进及已结束的记录，图表按实际观察日期展示。补记变化或结束跟进可从病程卡片回到健康对话。

在健康页面顶部可打开「新手指引」，搜索「病程」「随访提醒」或「导出健康记录」。

## 用药、随访与历史线索

- 「我的用药 → 通过对话记录」用于填写实际使用情况。已保存的记录可用「更正记录」发起核对，确认后写入。部分记录会展示匹配到的产品说明及来源，核对时注意地区、规格、剂型和版本。
- 通过健康对话提出随访时间，核对草稿后保存。到期事项显示在「每日健康 → 今天的待办」；点「和伙伴记录」回到对话，再核对并确认更新。「我的与隐私 → 提醒与待办」也可查看已保存事项。
- 「历史线索」展示匹配到的观察摘要、日期和知识来源。可以回到「我的病程」核对原始记录。

## 导出与清除

- 在「我的与隐私」点「导出我的记录」，下载 `health-records.json`。导出内容含对话与已保存记录，照片以附件引用呈现。
- 点「清除健康记录」后，先核对弹窗，再点「确认清除」。操作会清除健康对话、病程、用药、提醒、图片和健康背景，后台继续清理附件文件和模型检查点。伴AI 账户可继续使用。备份按部署保留期清理，默认 7 天。下载后的副本由使用者管理。

## 启用

在仓库根目录运行：

```sh
make health-init
```

脚本只在私有 `.env` 中补充缺少的随机密码及服务令牌。要开启对话，在同一个文件中配置支持图片、流式返回和 JSON 输出的兼容模型：

```dotenv
HEALTH_AGENT_PROVIDER=openai_compatible
HEALTH_MODEL_BASE_URL=https://your-model-provider.example/v1
HEALTH_MODEL_NAME=your-vision-model
HEALTH_MODEL_API_KEY=your-model-key
```

然后运行 `make docker-up-health`，打开 [伴 AI](http://localhost:3000) 并登录。普通 `make docker-up` 无需配置健康服务；点击健康助手会显示未启用提示。健康服务已启用但模型未配置时，仍可查看、导出和清除已有健康数据。开发联调可以使用 `HEALTH_AGENT_PROVIDER=test` 和 `HEALTH_ENABLE_TEST_PROVIDER=true`；测试输出只用于合成验收。

已有部署在基础 Compose 文件之后追加 `-f deploy/compose/compose.health.yml`，并在同一私有环境中配置这些变量。`health-migrate` 初始化独立健康库。健康 API 通过主 API 的认证网关访问，数据库、附件和备份使用独立卷。查看状态、跟踪日志或停止部署时使用相同的 Compose 文件和 profiles。

```sh
docker compose --profile app --profile agent --profile agent-runtime --profile observability --env-file .env \
  -f deploy/compose/compose.yml -f deploy/compose/compose.health.yml ps
```

若页面提示「健康助手尚未启用」，核对主 API 是否加载了健康 Compose 配置。若能进入健康空间但对话未连接 AI 服务，检查 `health-agent`、`health-worker` 和独立模型配置。模型恢复后可在原消息旁重试，保留已发送的文字和图片。

## 数据与维护

- 主 API 验证当前伴 AI 会话后，用服务令牌转发健康请求。健康服务通过账户 ID 区分记录；不会复制伴 AI 邮箱、密码、通用会话或长期记忆。每个用户在首次进入时创建一个空健康空间。
- 健康模型会接收生成当次回复需要的文字、照片和相关健康记录。配置外部模型前应确认服务提供方如何处理这些数据；健康模型凭据独立于伴 AI 通用模型。
- `HEALTH_BACKUP_KEEP_DAYS` 控制健康备份保留天数。健康模型由部署环境配置；主应用管理后台的「模型服务与路由」管理通用模型。
- 本集成未开放科研工作台、研究授权或 SciencePal。原项目已有账号、记录、附件及数据库不自动迁移。
- 隔离的健康 API 单元测试可用 `make test-health` 运行。健康服务来源和改动见 [服务说明](../services/healthy_care/README.md)。
