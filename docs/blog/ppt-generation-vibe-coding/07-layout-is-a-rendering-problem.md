# 排版不是 Prompt 问题：文字溢出、空页、字体和项目符号的渲染工程

内容正确之后，我曾经以为剩下只是“调模板”。真实情况恰好相反：PPT 排版是整个功能中最接近跨浏览器兼容性的一部分。PowerPoint、LibreOffice、预览服务和基于 OOXML 的自定义渲染器，对字体度量、自动缩放、项目符号和段落间距都有细微差异。

如果只检查 PPTX XML，很多问题永远看不见。

## 文字溢出：文本框没越界，不代表文字没越界

最早的布局门只检查形状矩形是否位于画布内。后来生成的页面中，正文框本身完全合法，最后两行文字却已经跑到框外并和页脚重叠。

修复分两层。渲染前，根据可用宽度、字号、CJK 字符宽度、段落数、行距和边距估算实际行数；估计容量不足时，优先调整页面分组与内容密度，再有限度降低字号。渲染后，把所有幻灯片转成图片，运行独立溢出检测并人工查看高风险页。

这里的顺序很重要：先减少一页承担的内容，再缩小字体。单纯把字缩到能塞下，通常只是把“溢出”变成“不可读”。

## 空页和内容缺失：不要把保守降级做成删除

另一次修复中，为了避免小字号文字重叠，系统把无法可靠布局的文本框直接清空，结果产生大量空页。用户给出的原则非常明确：字体太小无法识别时，保留原样，也不要留下空白；不缺内容优先于形式完美。

这条反馈后来变成通用降级顺序：

1. 尝试扩大或重排容器。
2. 尝试拆页，并保留来源上下文。
3. 在可读下限内调整字号和间距。
4. 无法安全改写时保留原内容或原页面快照。
5. 绝不以空白代替失败内容。

“失败时保留”不是偷懒，而是内容保真系统的重要策略。

## 字体与符号：声明字体还不够

简繁混合、方框符号和公式字符缺失，往往来自字体 fallback。PPTX 中写了字体名，不代表运行渲染器的容器里真的安装了它，也不代表项目符号使用同一字体。

我们最终统一了可部署的 CJK 字体，在镜像中安装并验证字体文件，同时为正文、项目符号和默认 run properties 显式设置字体。对公式、代码标识符和特殊数学符号，则避免经过会替换标点或字符宽度的普通本地化流程。

这也是为什么“在我的电脑上正常”不算验收。字体必须在实际部署镜像和独立渲染环境中都存在。

## 项目符号为什么会跑到文字上一行

这是排版迭代里最有代表性的误判。

症状是：第一个项目符号正常，后续较长条目的圆点会单独出现在上一行，文字从下一行开始。最初我怀疑模板继承了错误的项目符号；显式写入 `marL`、`indent`、`buChar` 和 bullet font 后，问题仍在。接着我把每个列表项拆成一个独立原生段落文本框，短条目好了，长 CJK 条目在部署渲染器中仍可能让圆点独占首行。

真正稳定的方案是把视觉职责拆开，但保留原生语义：

- `Native Bullet Marker N` 是一个只承载原生项目符号的单行文本框；
- `Bullet Text N` 是相邻的可编辑正文框；
- 两者使用相同 top、height、top inset、字号、字体和行距；
- marker 的右边界等于正文的左边界；
- 每一对和下一对之间使用几何间距，而不是依赖段落 `space_after`；
- 质量门逐一检查配对、原生 bullet OOXML 和垂直不重叠。

这样没有把 `•` 当普通字符写进正文，仍保留了原生项目符号配置，同时绕开了不同渲染器对“长 CJK 原生列表首行”的不一致处理。

## 为什么不依赖自动缩放

OOXML 的 `spAutoFit` 在不同渲染器里行为差异很大。有的缩字体，有的扩文本框，有的改变行距。为了得到可重复结果，关键正文框使用显式尺寸和可计算容量，自动行为只保留在风险可控的场景。

这会让代码比“设置 text_frame.auto_size”复杂，但好处是质量门可以判断：某个框预期占几行、需要多高、是否会碰到下一元素。可预测性比模板魔法更有价值。

## 布局质量门要看什么

我们逐步加入了这些检查：

- 形状是否超出画布；
- 正文估算高度是否超过容器；
- 表格行高和字体是否低于可读阈值；
- 图片是否被非等比拉伸或错误裁剪；
- 原生项目符号几何与字体是否完整；
- marker 与正文是否一一配对且同基线；
- 是否存在无可见内容的空页；
- 是否出现替代字符 `�`、未清理生产标记或繁体混入；
- 页面渲染后是否真实溢出。

最后一项无法被前面的结构检查完全替代。我们的发布流程会用真实失败输入生成整份 PPT，逐页渲染，再查看 montage 和高风险页面。项目符号修复就是在这一步推翻了两次“单测已通过”的结论。

Vibe Coding 的危险不在于改得快，而在于很容易把一个合理解释当成已经验证的事实。排版问题尤其需要“让渲染器说话”：代码和 XML 只能证明意图，像素结果才证明交付。
