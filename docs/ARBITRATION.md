# 证据仲裁

图版本 `ai-companion-supervisor@3.72.0`。协议为 `evidence-arbitration-v2`，覆盖审校意见、研究结论、Wiki 来源差异与长期记忆关系。保留 v1 历史记录读取；旧图的在途 Run 不能混用新图。

## 有界辩论（默认关闭）

`AGENT_DEBATE_MODE` 支持 `off`（默认）、`requested` 和 `on_conflict`。可信调度器在任务启动时冻结开关，恢复期间修改环境变量不会改变该任务的辩论规则；缺少开关快照的旧检查点不会自动启用。`requested` 要求用户明确提出辩论、独立/交叉核验或审校；`on_conflict` 对 Work 研究的可比较事实冲突、缺乏可追溯原文的候选，以及已有审校发现的问题启用。没有具体问题时不增加辩论调用。

执行顺序：冻结原始候选与证据 → 证据核验/反例核验两条隔离分支 → 汇合并保存独立性报告 → 仲裁 → 必要时补证 → 最多一轮交叉复核 → 裁决或保留分歧。

- **独立性**：首轮只提供冻结候选、任务约束和原始资料，不提供对方判断、前次仲裁或依赖分析。双方都落盘后才能交换质疑；第二轮标为交叉复核。报告记录输入指纹、参与者、模型配置、Prompt 版本和来源依赖。相同模型配置、相同来源或来源关系未知不能被当成统计独立，也不按多数票采纳结论。
- **补证**：`need_evidence` 可返回有界的 `evidence_requests`，协调器校验只读白名单、Schema 和动作预算后执行。重复工具/参数请求被剔除。原文片段先经过内容去重和相关词预筛，再由两方用逐字引文说明新增信息；没有共同确认的实质增量就不再仲裁。词法预筛是保守启发式，语义判断仍需模型评测。
- **来源**：文档查询只取原始 citations，Wiki 综合页只取原文 quotes，内置产品知识取版本化章节正文。模型生成的 answer、summary、工具提示语和抓取时间不能充当原始证据。新候选必须由补证复核分支登记，绑定前驱与新证据，仲裁不能自行生成候选。
- **收敛**：`call_status` 表示调用/协议是否成功；`resolution_status` 单独表示全部、部分或尚未解决；`termination_reason` 表示完成、无增量、超时、超预算、无可用来源等原因。仲裁必须逐项回应两方的依据和反证。引用匹配、结构校验及回答反证的字段要求不等于数学证明事实为真。
- **交付**：原始研究候选保存在 `research_candidates`，轮次历史只追加，`research_results` 为已采纳视图。最终回复只汇总当前有效争议。未解决的研究分歧阻止文件生成；未解决的辩论审校直接停止交付。已解决的修改要求仍最多修订一次并走现有复核，不再新开辩论会话。

每个 Run 最多一个会话、12 个争议、两轮、6 次新增模型调用、2 次新增只读查询。模型请求快照上限为 48,000 UTF-8 字节。失败调用计费，供应商超额消耗也计入总账。先为最终综合保留一份额度，审校为修订、复核等预留五份；两轮各两位核验者加一次仲裁，所有调用继续受原有 Run 总额和节点限额约束。正文生成与修订成本不包含在新增的 6 次内，但仍计入整个 Run。

会话保存 60 秒绝对截止时间，包含排队和异步等待，恢复不重置。真实 HTTP 工具和模型适配器按剩余时间收紧请求超时；检查点恢复复用已保存的分支和工具任务 ID。测试/开发适配器没有来源复验接口时明确标为未验证，不应作为生产接入方式。

Work 聊天会显示本次核验的结果、已解决项、轮次、补证次数与停止原因。刷新或重新打开会话后，最近一条回复的摘要通过需用户认证的 `GET /v1/agent-runs/{run_id}/evidence-review` 恢复，该接口只返回摘要与任务身份，不返回旧原文、回答和裁决理由；页面核对会话、任务和终态。恢复结果标明属于交付时的历史核验，不保证资料当前仍有效。新请求、普通回复不会继承旧摘要，迟到的恢复响应不会覆盖新任务。

摘要只公开有界计数、布尔状态与固定停止原因；服务端和页面均拒绝畸形计数，缺少来源或独立性校验不能显示全部解决。摘要不包含原文；来源版本、访问或快照失效时，公开 Run 接口也移除原始观察、候选与裁决理由，审计数据留在内部记录。

Wiki 可通过 `CONTEXT_WIKI_DEBATE_MODE=on_conflict` 在既有后台编译任务中启用两轮核验，默认 `off`。每组最多 6 次模型调用、2 次补读、60 秒；最多处理 3 个来源权限组。首轮两方独立提交，第二轮需共同确认新证据，裁决必须逐项回应反证。补读只限该页已有的完整来源权限交集，不隐式扩大可见范围。当前支持读取同一文档此前未纳入输入的其他原始 Chunk；不会自动扩展到其他文档，也不会从正文不足的片段推断遗漏内容。

Wiki 使用既有 `wiki_shards` 存储冻结来源/模型/协议对应的调用预留、输出和绝对截止时间。重启复用已完成结果，不能重置调用额度；调用已预留但响应未持久化时停止，不自动重发不确定的调用。来源权限和版本在每次模型批次、补读与最终采纳前复验；完整裁决可在有效来源下复用。来源改变会形成新快照。后台检查点不需要新增数据库表。

记忆继续使用单次仲裁。未解决或存在替代关系时，记录带相关记忆 ID 的具体澄清入口，页面显示两条相关记录及时间/情境确认问题。用户可选定其中一条进入纠正表单，输入时间或情境后明确保存；空内容不能保存，取消不修改数据，保存继续使用既有纠正接口。删除或失效来源会连同旧澄清项一起隐藏。

这些能力默认关闭；真实模型对照评测与生产灰度尚未执行。

## 来源与权限复验

新增内部只读接口 `POST /internal/v1/agent/runs/{run_id}/evidence/validate`，沿用服务令牌、运行租约、截止时间及 `X-Agent-Run-Revision`。用户身份由已持久化的 Work Run 决定，不接受 Python 指定的用户身份。

请求为 `{"references":[{"source_id":"原文文档 ID 或 product:章节 ID","version":"已冻结版本，首次可为空","chunk_id":"原始片段 ID","text":"实际原文摘录"}]}`，最多 48 项、96,000 字节。返回 `versions` 映射，不返回文档正文，也不扩大读取权限。服务端核对文档归属、当前状态、版本和原始 Chunk 内容；内置知识核对章节版本与正文。当前 Work 只读工具使用个人文档范围，接口遵循该范围。

启动、模型处理、恢复与最终交付边界重新校验来源。首次校验补齐文档查询中缺少的版本，后续版本变化或删除、权限失效会阻止旧证据继续进入模型或回复。原始证据不可用时明确保留分歧。此元数据校验不属于两次新增资料查询，不发起模型请求；同样受请求截止时间约束。

## 触发与行为

| 场景 | 触发条件 | 处理结果 |
| --- | --- | --- |
| 审校 | 专家提出了具体问题 | 仲裁可驳回误报、选择有效意见、合并重复或冲突意见，形成一份修订要求。修订后继续复核；最多修订一次。全部专家通过时不调用仲裁。 |
| 研究 | 相同主体、属性、范围和生效时间出现不同值 | 回查原始工具证据，只保留裁决选中的已有结论。其余候选仍在审计记录中。未解决的分歧会明确显示在最终回复；文件任务在分歧解决前停止生成。 |
| Wiki | 多来源同名页面出现“字段：值”差异 | 标记等价表述、范围差异、版本替代、矛盾或待核对；原文、引用、来源差异始终保留。版本替代必须引用带明确替代措辞的原文，上传时间不作为依据。 |
| 记忆 | 新建或编辑内容与同一用户已有记忆存在文本重合 | 标记兼容或冲突关系，同时保留双方。只有现有明确纠正接口可替代旧记录。未解决的关系会在召回的双方附提示，来源删除、修改或被替代后隐藏旧仲裁记录。 |

研究分析使用 `fact` 字段表达 `subject / predicate / value / scope / valid_at`，兼容旧适配器的简单“字段：值”输出。检测针对可比较的结构化事实，不保证识别所有自然语言矛盾。记忆候选采用字符二元组相似度，至少两个共同二元组、交并比不低于 0.25，最多检查 500 条活动记忆并选择前 8 个候选；该匹配只触发核对，不代表事实矛盾。

## 协议与边界

仲裁返回 `accept / reject / merge / retain / need_evidence`、候选 ID、理由及证据摘录。校验要求覆盖全部输入争议、候选来自对应争议、引用属于可见证据、摘录逐字匹配；采纳研究结论还须引用该候选的原始证据。依赖分支的分析 ID 会递归展开为原始工具证据，分析本身不充当事实来源。

仲裁只能处理语义意见。工具 Schema、来源权限、版本校验、动作预算、写操作审批和数据库 CAS 继续由原有确定性代码执行。来源文本及仲裁意见均作为参考资料，不能提升权限。所有参与者继续使用既有模型配置；没有通过增加不同模型来保证独立性。

## 单次仲裁的预算、持久化与隔离

- Agent 每份输入最多一次模型尝试，最多 12 个争议，完整输入不超过 48,000 UTF-8 字节。剩余额度分配一半给仲裁，保留最终综合/修订额度；每 Run 的仲裁节点最多 3 次模型调用。超限、失败或非法裁决均保留争议，不重试仲裁。
- `arbitrate_parallel` 是独立检查点节点。输入哈希包含协议、证据、候选、任务约束及模型配置；相同输入复核复用已保存裁决。失败调用和供应商超额用量仍计入预算。`arbitrations` 保存原始候选与裁决，模型事件包含 `arbitration_id`，并记录耗时、调用和费用。
- Go 仲裁每组最多一次请求，12 个争议、48 份证据、32,000 字节输入、3,000 输出 Token、8 秒截止时间。Wiki 按完全相同的来源权限依赖和来源版本分组，每次编译最多处理 3 个组，其他组明确保留争议。不同来源权限组不会共享模型上下文。
- Wiki 仲裁随页面 JSON 和版本历史持久化，权限仍取全部来源的交集。记忆仲裁保存在 `long_term_memories.arbitration`，绑定每个来源的内容哈希；列表和召回复用已读取的记忆集合校验关系，避免逐条增加数据库查询。Go 记录调用数与供应商返回的 Token 用量，不估算未提供的账单费用。

## 升级与验收

已有部署需应用 PostgreSQL `000045_memory_arbitration` 或 MySQL `000034_memory_arbitration`，并完成 Wiki 分片迁移。本次 v2 状态使用已有 JSON 和 LangGraph 检查点，无新增数据库列。API、Worker 与 Agent 镜像一同升级；旧图版本的未完成 Run 需先结束或重新发起。跨库迁移工具已包含记忆仲裁字段。

```sh
go test -race ./internal/arbitration ./internal/memory ./internal/document ./internal/agent ./internal/httpserver
make eval-agent-arbitration
make test-python
```

独立测试数据库可设置 `POSTGRES_TEST_DSN`、`MYSQL_TEST_DSN` 和 `LANGGRAPH_POSTGRES_TEST_DSN`，运行真实持久化与断开重连测试。新列支持 down/up 回滚验证；回滚会删除该列的仲裁记录。

验收用例覆盖无分歧跳过、误报驳回、有效修订合并、证据不足保留、伪造引用拒绝、预算不足/超额、同一候选缓存复用、来源版本失效、跨用户隔离与数据库恢复。CI 和 `make eval-agent` 包含确定性仲裁验收，报告位于 `artifacts/agent-eval/arbitration.xml`。真实模型的误拒率、错误采纳率、延迟和成本仍需以生产代表性样本测量，离线桩测试不代表线上准确率。

`make eval-agent-arbitration` 运行仲裁、辩论、交付和评测门槛测试。v2 的共享协议定义和跨语言正反例分别位于 [JSON Schema](contracts/evidence-arbitration-v2.schema.json) 与 [契约用例](contracts/evidence-arbitration-v2.cases.json)。新测试包括首轮上下文隔离、重复证据拒绝、跨轮有效裁决、逐节点恢复、异步读取复用、失效来源阻断、供应商超额计费和一次修订边界。

## 浏览器验收与评测门槛

仅开发模式可运行内置浏览器验收页：

```sh
cd web
DEBATE_PREVIEW=true NEXT_DIST_DIR=.next-debate pnpm dev --hostname 127.0.0.1 --port 3400
```

打开 `http://127.0.0.1:3400/dev/evidence-review`，分别执行新证据解决分歧、重复资料保留、来源失效、拒绝写入补证、关闭辩论。页面调用生产 LangGraph 和实际交付组件，模型与资料接口为明确标注的合成适配器，不访问用户数据或外部模型。刷新恢复场景使用当前标签页保存的合成 Run 测试共享恢复函数，记忆场景使用实际澄清卡与纠正表单、仅修改合成记录；不代表已验证真实登录、数据库交付或模型准确率。生产构建及未显式开启的开发服务均返回 404；执行接口限制同源本地请求、固定场景、单并发和 15 秒超时。命令行也可运行：

```sh
PYTHONPATH=workers/python/src workers/python/.venv/bin/python -m ai_companion_worker.evaluation.debate_scenarios resolved
```

四组完整 Run 对照的报告门槛已实现（不是自动线上灰度）：`baseline_single`、`single_supplement`、`repeat_same_evidence`、`debate`。人工标注结果与实际调用账单按相同任务、原始资料哈希、模型及预算配对。配置位于 `evals/agent/debate/thresholds.v1.json`，应在评测前确定；报告保存配置哈希，不能用合成数据、不完整费用、缺失对照组或超额 Run 获得通过。

```sh
PYTHONPATH=workers/python/src workers/python/.venv/bin/python -m ai_companion_worker.evaluation.debate_gate \
  --measurements artifacts/agent-eval/debate-measurements.jsonl \
  --thresholds evals/agent/debate/thresholds.v1.json \
  --report artifacts/agent-eval/debate-gate.json
```

输入字段定义及样例见 [评测格式](DEBATE_EVALUATION.md)。报告包含错误采纳、误驳回、解决率、错误共识、有效补证的样本数和 Wilson 95% 区间，以及 P95 延迟和完整 Run 费用。先要求错误采纳非劣性证据，再检查解决率、成本、延迟；单 Agent 补证或同资料重复判断不劣且费用更低或相同时，拒绝推广复杂方案。工具只读取评测记录，不修改交付、部署或流量。真实四组模型运行、人工标注和灰度发布仍需有代表性的真实样本，不能用当前合成验收替代。
