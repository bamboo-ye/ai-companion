# 伴AI：开发实施计划

> 文档状态：M0-M4、M6、M8 后端平台完成；M5 金融研究和 M7 原生双端按产品决策跳过
> 编制日期：2026-07-01  
> 对应设计：`docs/DETAILED_DESIGN.md`

## 1. 交付策略

采用“可运行的纵向切片”而不是按数据库、后端、前端长期横向分工。每个迭代都交付一条用户能验证的完整路径，并同步补齐日志、指标、安全和测试。

建议分为三次产品发布。当前完成口径以 Web/后端平台 1.0 内测为边界，明确跳过 M5 金融研究和 M7 原生双端扩展：

- **MVP / 内测版**：角色对话、短消息、基础记忆、文档问答、记账、计划提醒、基础工作 Skill。
- **Beta / 公测版**：完整 RAG、动态降级和运营能力。金融分析页面与 Android/iOS 原生核心链路在本完成口径中跳过。
- **1.0**：Web/后端平台完成团队协作、邮件投递/重放、订阅配额、未成年人模式、管理员后台、MFA、审计、发布证据链和规模化运行手册。

工作量按“2 名 Go/AI 工程师 + 1 名 Web 工程师 + 1 名 Android 工程师 + 1 名 iOS 工程师 + 兼职设计/测试”估算。Web MVP 约 10～12 周，含原生双端的 Beta 累计约 18～24 周，包含团队/计费/真实邮件/未成年人模式/管理后台的 1.0 累计约 26～34 周。若只有 3 人团队，预计需 30～40 周并顺序交付双端。模型/数据供应商审批和应用商店审核不计入编码工期。

## 2. 里程碑

### M0：范围冻结与工程初始化（第 1 周）

目标：所有人基于同一范围、目录和验收定义工作。

任务：

- 在已确认目录 `/Users/windcry1/Documents/code/ai_companion` 初始化 Git、分支策略和环境配置方式。
- 评审 MVP 范围和用户旅程；对尚未确定的数据区域、保留期、模型和成本使用配置化边界。
- 对候选模型做质量、延迟、价格、隐私和区域小型 bake-off，并形成选型记录。
- 建立 Go module、Python Worker、Web、Android Compose、iOS SwiftUI 工程骨架、Makefile/Taskfile、lint、单元测试和 CI。
- 创建 Docker Compose：MySQL、Redis、Kafka KRaft、Qdrant、MinIO、可观测性最小组件。
- 建立配置、密钥、数据库迁移、OpenAPI 与事件 schema 管理规范。
- 将两张视觉参考图纳入品牌资产目录，并确认其版权/使用范围。

验收：

- 新机器按 README 一条命令启动依赖和应用。
- CI 完成格式、lint、单测、依赖漏洞和镜像构建。
- 环境中不提交真实密钥；示例配置可运行。
- MVP backlog 每项有验收标准和明确负责人。

### M1：账户、角色与可靠聊天（第 2～3 周）

目标：交付第一个可体验的情感陪伴纵向切片。

任务：

- 注册/登录/刷新/退出、设备与时区。
- 角色 CRUD、persona 编译与版本管理。
- 会话/消息模型、消息发送接口、任务接受状态。
- 模型适配层、流式生成、取消、重试、超时。
- 语义拆气泡、拟人化间隔、消息顺序与断线重连。
- Redis 在线状态与实时事件；MySQL 未读补拉。
- Web 首页、角色创建和聊天页；粉/黄/蓝模块令牌与通用组件。
- 基础内容安全、限流、token/成本记录。

验收：

- 创建两个不同角色，同一测试问题表现出稳定、可测的人格与风格差异。
- 长回答拆成有语义的 2～5 个气泡，停止生成后不再新增内容。
- 刷新页面或离线重连后消息不丢、不重、不乱序。
- 模型超时显示可恢复状态，用户可重试。

### M2：上下文、长期记忆与基础 RAG（第 4～5 周）

目标：系统能记得有价值的信息，并能基于上传文档回答且给出处。

任务：

- token 预算近期窗口、滚动摘要、日期衰减。
- 记忆候选提取、无效对话过滤、去重、冲突与敏感分类。
- 记忆查看/编辑/固定/删除 UI。
- 文件上传、对象存储、异步任务状态和病毒/类型检查。
- 文本 PDF 页级解析、结构切片、Embedding 与 Qdrant 索引。
- dense/sparse 混合召回、RRF、引用页码和证据不足策略。
- 建立 100～300 条对话/RAG 离线评测集和基线指标。

验收：

- “记住我不吃香菜”可在后续相关对话正确使用，删除后不再召回。
- “你好/谢谢”等无效内容不产生长期记忆。
- 文档回答可跳转到正确页；无证据问题不编造答案。
- 重复上传/重复消费不生成重复索引，删除文档后无法继续检索。

### M3：生活助手（第 6 周）

目标：通过聊天安全地完成记账、每日计划与提醒。

任务：

- 金额/币种/收支/分类/时间抽取和确认卡。
- 账单 CRUD、筛选、月度汇总与 Excel 导出。
- 计划/计划项/提醒领域模型和时间解析。
- 从对话与应用内备忘录生成每日计划候选。
- 应用内通知中心、系统提醒映射/同步模型与本应用 APNs/FCM 推送接口。
- 幂等、撤销、时区/DST 和重复提醒测试。

验收：

- “昨晚打车 36 元”回显绝对日期、分类和金额，确认一次只产生一笔账。
- Excel 导出数据、公式/汇总与系统记录一致。
- 模糊时间先确认；跨时区后仍在预期本地时间提醒。
- 未授权通知时给出清晰状态，不声称已设置系统闹钟。
- 系统提醒未授权、同步失败或发生冲突时状态可见，应用内记录不会丢失或重复。

### M4：Skill 平台与办公能力（第 7～8 周）

目标：形成可扩展工具框架并交付首批工作技能。

任务：

- 分层意图路由、Tool Schema、权限、确认、预算、超时与审计。
- 显式 Agent 状态图、检查点、重试与失败补偿。
- Skill 清单、版本、启停、输入/输出契约和测试夹具。
- MCP client 适配器及工具白名单。
- 翻译、邮件草稿、文档编辑、PPT 大纲/生成、CSV/XLSX 分析。
- 工作伙伴技能大厅、文件选择器、任务进度和结果页。

验收：

- 新增一个无副作用 Skill 无需改聊天核心模块。
- 需要确认的 Tool 在未确认前不会执行；重复确认不重复执行。
- 任务可取消、可重试、可查步骤和失败原因。
- 生成文件可下载且源文件不会被默认覆盖。

### M5：金融研究 MVP（第 9～10 周）

> 2026-07-06 产品决策：跳过 M5，不进入当前开发序列。由于尚无合法金融数据源、账号和授权，不创建占位金融流水线；后续只有在重新明确范围与数据授权后才恢复。

目标：对用户提供的十年价格 Excel 生成可追溯、可复现的分析页面。

任务：

- 数据识别、清洗报告、单位与频率标准化。
- 确定性指标、阶段候选、异常点与图表节点计算。
- 权威资料搜索/导入接口、来源快照和引用模型。
- 驱动因素归类：供需、政策、产能、成本、宏观和突发事件。
- 核心结论、阶段分析、情景展望、风险和免责声明。
- 交互 HTML 报告与 PDF/PPT 导出。
- 建立多种格式的金融金标数据集和数值回归测试。

验收：

- 清洗后的行数、修改原因和单位变换可追溯到原始行。
- 页面所有关键数值与确定性计算结果一致。
- 事件和外部观点均有来源、发布日期和访问日期；系统推断被明确标注。
- 图中关键时间、价格节点和正文阶段一致。
- 数据不足时不给伪精确预测。

### M6：可靠性、动态降级与内测发布（第 11～12 周）

目标：在失败和突发流量下仍保存请求、可恢复并可观测。

任务：

- Outbox/Inbox、重试、DLQ、人工重放与补偿工具。
- 队列 lag/年龄监控、L0～L3 降级控制器、滞回与恢复。
- OpenTelemetry、核心 dashboard、告警、SLO 和运行手册。
- 权限审计、提示词注入、文件攻击、越权、依赖漏洞测试。
- 备份/恢复、数据导出/删除、保留策略。
- 容量与故障压测、内测埋点、反馈入口。
- Web PWA 部署、灰度、回滚和版本说明。

验收：

- 杀死 worker 或临时关闭模型服务，已接受任务不丢，恢复后可继续或明确失败。
- 同一事件重复投递不产生重复副作用。
- 触发积压时降级符合矩阵，恢复不抖动。
- 达到设计中的 MVP SLO，完成一次从备份恢复演练。

### M7：Android/iOS 原生双端与 Beta（第 13～24 周）

> 2026-07-11 产品决策：跳过 M7，不进入当前完成口径。M0/M3 已保留 Android/iOS 工程骨架和系统提醒适配器边界；原生双端完整产品化、商店材料和端到端 Beta 验收后续另行立项。

目标：Android/iOS 原生应用覆盖核心旅程，并提供伴AI 应用内提醒与推送。

任务：

- Android：Kotlin + Jetpack Compose 实现登录、首页、角色、聊天、文件、任务、计划和设置。
- iOS：Swift + SwiftUI 实现相同核心旅程。
- 两端分别完成 WebSocket/SSE 重连、后台/前台切换、文件上传、图片缓存和安全存储。
- iOS EventKit Reminders 创建、读取、更新、完成、权限撤回与冲突处理。
- Android Calendar Provider 事件提醒、AlarmManager/通知；按需申请并检查精确闹钟权限。
- Google Tasks OAuth 作为可选连接器，不假定所有 Android 厂商共享同一任务库。
- APNs/FCM、深链和系统权限引导。
- 无障碍、弱网、不同屏幕尺寸和耗电测试。
- TestFlight/内测渠道发布、隐私清单与商店材料。

验收：

- Android/iOS 完成核心 E2E；前后台切换不丢事件。
- 用户撤销通知权限后系统状态正确同步。
- 同一提醒在应用内与系统端完成/修改后可同步；重复同步不产生重复条目。
- 崩溃率、启动时间和消息到达率达到 Beta 门槛。

### M8：协作、商业化、合规与 1.0（第 25～34 周）

目标：交付已确认的 1.0 Web/后端平台能力，并补齐内测发布、运营和合规证据链。

- 邮件投递、失败重放与审计；当前仓库提供 SMTP/Noop sender 和运维重放，邮箱 OAuth 连接器后续按供应商授权扩展。
- 团队工作区、成员角色、邀请、共享文件/任务和私人数据隔离。
- 订阅套餐、服务端配额和超额策略；支付供应商 Webhook 后续按商业模式和地区补充。
- 未成年人模式、监护同意框架、更严格安全策略和地区化合规准备。
- 管理后台、MFA、任务/DLQ、内容安全工单、模型/Skill 灰度、成本配额和滥用处理。

- 团队成员不能读取未共享的私人陪伴会话与记忆，权限变更有审计。

## 4. Definition of Done

每项功能只有同时满足以下条件才算完成：

- 验收标准由产品或用户场景验证通过。
- API/事件 schema 更新且向后兼容或有迁移方案。
- 单元与必要的集成/E2E 测试通过，AI 功能通过对应评测门槛。
- 权限、幂等、错误、超时、取消、审计和数据删除已考虑。
- 日志、指标、trace 和告警可定位失败，不记录敏感正文。
- 数据库迁移可前滚；发布有灰度和回滚方案。
- README/运行手册/用户说明同步更新。
- 无高危依赖漏洞、硬编码密钥和已知越权问题。

## 5. 质量门禁

建议在进入内测前设定并冻结数值门槛：

- Go/Python/Web/Android/iOS 核心模块测试覆盖率目标，不以覆盖率替代关键分支测试。
- 对话人格一致性、简短度、无效记忆过滤、记忆准确率。
- 意图路由 macro-F1、Tool 参数准确率、危险工具未授权执行率必须为 0。
- RAG context precision/recall、引用正确率、忠实度。
- 金融数值与金标误差、来源覆盖率、无来源事实率。
- p50/p95/p99 延迟、错误率、每次成功任务模型成本。
- 重复事件、崩溃恢复、断线补拉和降级演练结果。

具体阈值需用首个评测基线确定，不能用“看起来不错”作为发布标准。

## 6. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 首版范围过大 | 工期失控、核心体验不精 | 固定 MVP，视频和深度外部集成后置 |
| 多模型/多框架堆叠 | 难调试、成本高 | 供应商适配层；显式状态机；先基线后增加模型 |
| Kafka 对早期团队运维偏重 | 本地与线上复杂 | 数据库租约调度作为默认；Kafka 仅在达到水平扩展指标后通过独立 Compose profile 启用 |
| 记忆错误或令人不适 | 信任受损 | 高门槛提取、来源可见、敏感同意、可编辑删除 |
| RAG 解析复杂 PDF 失败 | 引用错误 | 页级质量分、OCR/视觉降级、低质量提示和回归集 |
| 自动记账/提醒误执行 | 数据污染、错过事项 | 候选卡确认、幂等、撤销、移动端权限状态 |
| 金融分析幻觉或合规风险 | 错误决策、法律风险 | 数值代码化、强制引用、事实/观点/推断分层、免责声明 |
| 外部模型/数据源中断 | 功能不可用 | 熔断、重试、降级、供应商适配与任务排队 |
| 图片/文件隐私与版权 | 泄露/侵权 | EXIF 清理、短链、访问隔离、来源与许可记录 |
| Web/Android/iOS 同时开发 | 人力和行为一致性压力大 | 先用 Web 验证 API；双端各有负责人，共享契约/令牌/E2E 用例而非 UI 代码 |
| 首发地区和模型未定 | 合规、延迟与成本可能返工 | M0 供应商 bake-off；区域/保留/路由配置化；冻结地区后做专项评审 |
| 无金融数据授权 | 无法提供稳定实时行情与付费研报 | 首版仅处理用户合法上传数据/资料；来源白名单；获得授权后再加连接器 |
